## Краткое резюме решения

**Проблема.** Монолит TradeWare обрабатывает отчёты по остаткам построчно
в онлайн-режиме. 400 000 строк в сутки, пики до 1,2 млн, 100–150
параллельных загрузок — система не выдерживает, транзакционные ресурсы
PostgreSQL перегружены, наблюдаемости нет.

**Решение.** Внедрить **Spring Batch** как batch-фреймворк для пакетной
обработки отчётов. Chunk-oriented processing вместо построчных UPDATE,
транзакционность на уровне чанка, встроенные retry/skip/restart,
поддержка partitioning и multi-threaded step.

**Как запускается.** Внутри Spring Boot приложения — **Spring Scheduler**
(`@Scheduled` с polling). Воркер работает постоянно, опрашивает GCS на
предмет новых файлов и запускает Spring Batch Job. Поток отчётов
постоянный — воркер должен быть готов обработать новую порцию в ближайшие
минуты, а не просыпаться раз в сутки по внешнему cron.

**Где разворачивается.** Docker-контейнер на Compute Engine VM в GCP,
рядом с монолитом. Без Kubernetes и без внешних планировщиков — минимум
новых инфраструктурных компонентов.

**Наблюдаемость.** Micrometer → Prometheus → Grafana (метрики),
Loki/ELK (централизованные логи).
